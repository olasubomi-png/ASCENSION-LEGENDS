# ASCENSION LEGENDS — Database Schema Reference

> **Scope:** Consolidated reference for all 24 MongoDB collections. Each collection entry documents the full document shape, indexes, and operational notes. Redis key patterns are documented at the end.
>
> **Conventions:**
> - All `_id` fields are MongoDB ObjectIds unless noted.
> - `createdAt` / `updatedAt` timestamps are ISO 8601 UTC.
> - `deletedAt` is present on soft-deleted documents; `null` means the document is live.
> - IDs generated by the application (not Mongo) use ULID format: `prefix_01J...` for readable prefixing.
> - Currency values are always integers (e.g., gold stored as integer number of coins).

## 1. `users`

Primary user identity document, one per Discord account.

```typescript
{
  _id: ObjectId,
  userId: string,              // ULID — "user_01J..."
  discordId: string,           // Discord Snowflake — unique
  username: string,            // Discord username
  globalName: string | null,   // Discord display name
  avatar: string | null,       // Discord avatar hash

  accountStatus: "active" | "banned" | "suspended",
  isPremium: boolean,
  premiumTier: 0 | 1 | 2 | 3,
  premiumExpiry: Date | null,
  isBeta: boolean,

  activeCharacterId: ObjectId | null,  // ref: characters

  registeredAt: Date,
  lastActiveAt: Date,
  lastLoginAt: Date,
  loginCount: number,           // integer, total login count

  preferences: {
    language: string,           // ISO 639-1, default "en"
    notificationsEnabled: boolean,
    renderQuality: "low" | "medium" | "high",
    autoEquipBestGear: boolean
  },

  createdAt: Date,
  updatedAt: Date,
  deletedAt: Date | null
}
```

**Indexes:**
```
{ discordId: 1 }           UNIQUE
{ userId: 1 }              UNIQUE
{ accountStatus: 1 }
{ isPremium: 1 }
{ registeredAt: -1 }
{ lastActiveAt: -1 }
{ deletedAt: 1 }           (sparse — only indexes non-null values)
```

## 3. `characters`

Playable characters owned by users. Users may have multiple characters.

```typescript
{
  _id: ObjectId,
  characterId: string,         // ULID — "char_01J..."
  userId: ObjectId,            // ref: users
  discordId: string,           // denormalized

  name: string,                // character name, 2–24 chars
  classId: string,             // e.g. "warrior", "mage", "rogue"
  subclassId: string | null,   // unlocked at level 30
  awakening: 0 | 1 | 2 | 3 | 4 | 5,  // awakening tier

  level: number,               // 1–100
  experience: number,          // total XP
  experienceToNextLevel: number,

  // Base stats (before equipment)
  stats: {
    hp: number,
    maxHp: number,
    mp: number,
    maxMp: number,
    attack: number,
    defense: number,
    magicAttack: number,
    magicDefense: number,
    speed: number,
    luck: number,
    critRate: number,       // float 0.0–1.0
    critDamage: number,     // float, e.g. 1.5 = 150% crit damage
    evasion: number,        // float 0.0–1.0
    accuracy: number        // float 0.0–1.0
  },

  // Derived / computed (updated after equip/unequip/level up)
  derivedStats: {
    effectiveAttack: number,
    effectiveDefense: number,
    battlePower: number,     // computed battle power rating
    resistances: {
      fire: number,
      ice: number,
      lightning: number,
      dark: number,
      holy: number
    }
  },

  equippedSkills: {
    slot1: string | null,   // skill id
    slot2: string | null,
    slot3: string | null,
    slot4: string | null,
    ultimate: string | null
  },

  passiveSkills: string[],  // list of passive skill ids

  locationId: string,       // continent id
  zoneId: string,           // zone within continent

  cooldowns: {
    lastBattleAt: Date | null,
    lastPvpAt: Date | null,
    lastDungeonAt: Date | null,
    lastDailyRewardAt: Date | null,
    lastExpeditionAt: Date | null,
    lastFishingAt: Date | null
  },

  isActive: boolean,         // only one character active per user
  isDeleted: boolean,

  statPoints: number,        // unspent stat points
  skillPoints: number,       // unspent skill points

  createdAt: Date,
  updatedAt: Date,
  deletedAt: Date | null
}
```

**Indexes:**
```
{ characterId: 1 }              UNIQUE
{ userId: 1 }
{ discordId: 1 }
{ userId: 1, isActive: 1 }
{ classId: 1, level: -1 }
{ "derivedStats.battlePower": -1 }
{ locationId: 1, zoneId: 1 }
{ deletedAt: 1 }                (sparse)
```

## 5. `economy_ledger`

Immutable transaction log. Every gold/gem credit or debit is a document here.

```typescript
{
  _id: ObjectId,
  transactionId: string,       // ULID — "txn_01J..."
  userId: ObjectId,            // ref: users
  discordId: string,           // denormalized

  type: "credit" | "debit" | "transfer_in" | "transfer_out",
  amount: number,              // positive integer
  currency: "gold" | "gems" | "seasonal_tokens",

  reason: string,              // machine-readable reason key, e.g. "battle_reward"
  description: string | null,  // human-readable

  balanceBefore: number,
  balanceAfter: number,

  // Optional context for why the transaction occurred
  relatedEntityType: "battle" | "quest" | "trade" | "shop" | "admin" | "system" | null,
  relatedEntityId: string | null,

  performedBy: "system" | "player" | "admin",
  performedByDiscordId: string | null,  // admin discord id if performed by admin

  createdAt: Date              // immutable — no updatedAt
}
```

**Indexes:**
```
{ transactionId: 1 }           UNIQUE
{ userId: 1, createdAt: -1 }
{ discordId: 1, createdAt: -1 }
{ currency: 1, createdAt: -1 }
{ reason: 1 }
{ createdAt: -1 }              (TTL: retain 2 years)
```

**Notes:**
- This collection is append-only. Documents are never updated or hard-deleted.
- A TTL index after 2 years (730 days) trims the oldest records for storage management.
- Aggregate balance is always read from `wallets`, not computed from this collection.

## 7. `inventory`

Item instances owned by players. Each document = one item stack.

```typescript
{
  _id: ObjectId,
  inventoryId: string,         // ULID — "inv_01J..."
  userId: ObjectId,            // ref: users
  discordId: string,           // denormalized
  characterId: ObjectId | null,  // null = account-wide storage

  itemId: string,              // ref: items_catalog
  quantity: number,            // integer ≥ 1
  isStackable: boolean,        // copied from item definition

  isEquipped: boolean,
  equippedSlot: string | null, // "weapon", "helm", "chest", etc.

  isLocked: boolean,           // true when listed on marketplace or in active trade
  lockReason: "marketplace" | "trade" | null,
  lockRefId: string | null,    // ID of the listing or trade

  enchantmentLevel: number,    // 0–10
  enchantmentStats: {
    [stat: string]: number
  },
  refinementLevel: number,     // 0–15

  acquiredFrom: string,        // "dungeon_drop", "shop_purchase", "trade", "admin_grant", etc.
  acquiredAt: Date,

  durability: number | null,   // null = infinite (for non-weapon items)
  maxDurability: number | null,

  createdAt: Date,
  updatedAt: Date,
  deletedAt: Date | null
}
```

**Indexes:**
```
{ inventoryId: 1 }                       UNIQUE
{ userId: 1 }
{ discordId: 1 }
{ characterId: 1 }
{ userId: 1, itemId: 1 }
{ userId: 1, isEquipped: 1 }
{ isLocked: 1 }
{ itemId: 1 }
{ deletedAt: 1 }                         (sparse)
```


## 10. `battles`

Battle records. Every PvP or PvE encounter generates one document.

```typescript
{
  _id: ObjectId,
  battleId: string,            // ULID — "battle_01J..."

  type: "pvp" | "pve" | "dungeon" | "raid" | "boss",
  status: "pending" | "simulating" | "rendering" | "completed" | "failed" | "error",

  // Seed used for deterministic simulation
  seed: number,
  engineVersion: string,       // battle engine semver

  attacker: {
    userId: ObjectId,
    discordId: string,
    characterId: ObjectId,
    characterName: string,
    classId: string,
    level: number,
    battlePower: number,
    snapshotStats: Record<string, number>  // frozen at battle start
  },

  defender: {
    userId: ObjectId | null,   // null for PvE opponents
    discordId: string | null,
    characterId: ObjectId | null,
    characterName: string,
    classId: string,
    level: number,
    battlePower: number,
    npcTemplateId: string | null,
    snapshotStats: Record<string, number>
  },

  winnerId: ObjectId | null,         // characterId of winner
  winnerDiscordId: string | null,
  winnerType: "attacker" | "defender" | "draw" | null,

  rounds: number | null,             // total rounds in the battle
  endReason: string | null,          // "hp_zero", "timeout", "forfeit"

  rewards: {
    attackerGold: number,
    attackerExp: number,
    defenderGold: number,
    defenderExp: number,
    itemDrops: { itemId: string, quantity: number }[]
  },

  // Render assets (populated after render job completes)
  gifUrl: string | null,
  mp4Url: string | null,
  renderJobId: string | null,
  renderedAt: Date | null,

  discordGuildId: string | null,  // Discord server where battle was initiated
  channelId: string | null,

  simulationDurationMs: number | null,
  renderDurationMs: number | null,

  // Full replay stored as sub-document (large — not fetched by default)
  replay: BattleReplayDocument | null,

  startedAt: Date,
  completedAt: Date | null,
  createdAt: Date,
  updatedAt: Date
}
```

**Indexes:**
```
{ battleId: 1 }                    UNIQUE
{ "attacker.discordId": 1, createdAt: -1 }
{ "defender.discordId": 1, createdAt: -1 }
{ type: 1, status: 1 }
{ status: 1 }
{ discordGuildId: 1, createdAt: -1 }
{ createdAt: -1 }
{ createdAt: 1 }                   (TTL: 180 days for completed battles)
```

## 25. Redis Key Patterns

Redis is used for caching and distributed coordination. All keys use a structured prefix scheme.

### Key Format Convention
```
{namespace}:{entity_type}:{entity_id}[:{sub_key}]
```

### TTL Conventions

| Tier | Duration | Used For |
|------|----------|---------|
| Hot | 60s | Leaderboard snapshots, active battle data |
| Warm | 300s | Character stats, wallet balance |
| Standard | 1800s | User profile, guild data |
| Cold | 86400s | Item catalog entries |

---

### Cache Keys

| Key Pattern | TTL | Value | Notes |
|-------------|-----|-------|-------|
| `cache:user:{discordId}` | 300s | Serialized user doc | Invalidated on user update |
| `cache:profile:{discordId}` | 300s | Serialized profile doc | Invalidated on profile update |
| `cache:character:{characterId}` | 300s | Serialized character doc | Invalidated on equip/level up |
| `cache:wallet:{discordId}` | 60s | `{gold, gems, tokens}` JSON | Write-through on every transaction |
| `cache:guild:{guildId}` | 600s | Serialized guild doc | Invalidated on member change |
| `cache:item:{itemId}` | 86400s | Serialized item catalog entry | Invalidated on catalog update |
| `cache:equipment:{characterId}` | 300s | Serialized equipment doc | Invalidated on equip/unequip |
| `cache:leaderboard:gold:top100` | 60s | JSON array of top 100 | Rebuilt by scheduler |
| `cache:leaderboard:season:top100` | 60s | JSON array of top 100 | Rebuilt by scheduler |
| `cache:world_boss:{bossId}:hp` | 10s | Integer current HP | Updated on every attack |
| `cache:world_boss:active:{discordGuildId}` | 30s | JSON list of active boss IDs | |
| `cache:battle:{battleId}:status` | 300s | Status string | Checked by polling clients |
| `cache:dau:today` | 300s | Integer DAU count | |

---

### Distributed Locks (Redlock)

| Key Pattern | TTL | Purpose |
|-------------|-----|---------|
| `lock:wallet:{discordId}` | 5000ms | Prevent concurrent economy operations |
| `lock:equip:{characterId}` | 2000ms | Prevent concurrent equip changes |
| `lock:trade:{tradeId}` | 10000ms | Lock both parties during trade execution |
| `lock:guild_bank:{guildId}` | 5000ms | Prevent concurrent guild bank operations |
| `lock:marketplace:list:{inventoryId}` | 5000ms | Prevent duplicate listings |
| `lock:boss_attack:{bossId}:{discordId}` | 3000ms | Rate-limit attacks per player per boss |
| `lock:daily_reward:{discordId}` | 60000ms | Idempotent daily reward claim |

---

### Cooldown Keys

| Key Pattern | TTL | Notes |
|-------------|-----|-------|
| `cd:battle:pvp:{discordId}` | Dynamic | Set to cooldown duration on battle end |
| `cd:battle:dungeon:{discordId}` | Dynamic | Per-dungeon type cooldown |
| `cd:daily_reward:{discordId}` | Until midnight | Reset daily |
| `cd:raid_join:{discordId}` | Dynamic | Cooldown after leaving raid early |

---

### Session / Presence Keys

| Key Pattern | TTL | Notes |
|-------------|-----|-------|
| `presence:{discordId}` | 300s | Updated by heartbeat; absence = offline |
| `battle:active:{discordId}` | 600s | Marks user as in-battle |
| `raid:active:{discordId}` | 3600s | Marks user as in-raid |
